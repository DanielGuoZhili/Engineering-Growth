**Two Sum：用 Map 在一次遍历中寻找配对**

### 我的原始内容

原稿包含 JavaScript 与 Python 两种 `twoSum` 实现。我的主要观察是：算法本身不难，当前更需要恢复对两门语言内置工具的熟悉度，尤其是 JavaScript `Map` 的 `has`、`get`、`set`，以及 Python 的 `enumerate`。我也希望 Saber 判断思路是否正确，并补全遗漏。

JavaScript 原始代码：

```javascript
/**
 * @param {number[]} nums
 * @param {number} target
 * @return {number[]}
 */
var twoSum = function(nums, target) {
    const map = new Map();

    for(let i = 0; i < nums.length; i++){
        let num = nums[i];
        let complement = target - num;

        if(map.has(complement)){
            return[map.get(complement), i];
        }

        map.set(num, i);
    }

};
```

Python 原始代码：

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        # 1. 设定一个空的字典作为容器（用来存：数字 -> 下标）
        seen = {}

        # 2. 遍历数组：用 enumerate 同时拿到下标 i 和当前数字 num
        for i, num in enumerate(nums):

            # 3. 计算补数
            complement = target - num

            # 4. 检查补数在不在字典里
            if complement in seen:
                # 如果在，说明找到了！返回之前那个数的下标和当前的下标 i
                return [seen[complement], i]

            # 如果不在，把当前的数字和下标存进字典，留给后面查
            seen[num] = i
```

### Saber 的整理

两种实现采用同一个“边遍历、边查找”的算法模式：

1. `map` 保存已经遍历过的数字，以及它们对应的下标。
2. 遍历到 `nums[i]` 时，计算与它组成 `target` 所需的另一个数字 `complement`。
3. 如果 `complement` 已经在 `map` 中，就返回旧下标和当前下标。
4. 如果不存在，再把当前数字和下标放入查找表，供后面的元素使用。

JavaScript 用一个 `Map` 实例表达“数字 → 下标”；如果改写成 TypeScript，可以把它标注为 `Map<number, number>`。Python 用 `dict[int, int]` 表达同一映射。`enumerate(nums)` 只是让 Python 在遍历元素时同时提供下标和值，不改变算法本身。

这里最关键的顺序是**先查找，再写入当前元素**。这避免了在某些输入中把同一个下标使用两次，同时仍能正确处理 `[3, 3]`、`target = 6` 这种需要两个相同数值的情况。

### Saber 的审阅与点评

**结论**：Master 的整体思路正确，而且 JavaScript 与 Python 版本是同一算法的忠实对应。在 LeetCode Two Sum 的常见约定——恰好存在一个答案，并且同一个元素不能使用两次——下，进入第 `i` 次循环时，查找表只包含下标小于 `i` 的元素；如果补数存在，返回的一定是两个不同下标。

**复杂度**：在 JavaScript `Map` 查找和写入平均为常数时间的假设下，时间复杂度是 `O(n)`，额外空间复杂度是 `O(n)`。这里的 `O(1)` 查找是平均情况的实现假设，不应表述成对所有哈希表实现都无条件成立。

**边界情况**：

- 重复数字：先查后存的顺序可以处理 `[3, 3]`。
- 负数与零：补数计算仍然适用。
- 没有答案：函数会自然返回 `undefined`。如果题目不保证一定有答案，需要先明确期望是返回空数组、抛错，还是返回其他值。
- 多个答案：当前实现返回遍历过程中最先发现的一组；是否符合要求取决于题目约定。

**代码表达可以改进的地方**：JavaScript 中的 `num` 和 `complement` 在每轮循环中都不会重新赋值，使用 `const` 能更准确表达意图；`return [`、`for (` 等空格调整可以提升可读性。这些是风格改进，不影响核心算法正确性。Python 版本在题目保证有答案时没有问题；若题目不保证有答案，类型标注 `-> list[int]` 与实际可能隐式返回 `None` 不一致，需要改成 `list[int] | None`，或者明确约定无答案时的行为。

**本地验证结果**：JavaScript 与 Python 两个版本在以下 5 组测试中结果一致且符合预期；这是本地函数级验证，不代表已经在 LeetCode 提交通过。

### Q-20261101-001

**`enumerate`、`Map` 应该称为内置方法还是对象？**

**问题**

Python 的 `enumerate` 和 JavaScript 的 `Map` 应该怎样准确称呼？它们是内置方法，还是对象？

**结论**

- Python `enumerate` 是**内置函数（built-in function）**。调用它会返回一个 `enumerate` 迭代器对象；遍历时依次产生 `(下标, 元素)` 二元组。
- JavaScript `Map` 是语言提供的**内置对象类型/内置构造函数**；`new Map()` 创建一个 `Map` 实例。
- `map.has()`、`map.get()`、`map.set()` 是 `Map` 实例使用的**方法**，更准确地说是定义在 `Map.prototype` 上的实例方法。
- Python 代码里的 `seen = {}` 创建的是一个 `dict`（字典）对象。`complement in seen` 使用的是成员运算符，`seen[num] = i` 是按键写入；它们都不应称为 `dict` 方法。

**分析**

可以用下面这组层次来记忆：

| 代码 | 准确称呼 | 作用 |
| --- | --- | --- |
| `enumerate` | Python 内置函数 | 把可迭代对象包装成“下标 + 元素”的迭代器 |
| `enumerate(nums)` | `enumerate` 迭代器对象 | 迭代时产生 `(index, value)` |
| `Map` | JavaScript 内置对象类型 / 构造函数 | 描述键值映射集合 |
| `new Map()` | `Map` 实例对象 | 保存本题中的“数字 → 下标” |
| `map.has/get/set` | `Map` 的实例方法 | 检查、读取、写入键值 |
| `{}` / `dict()` | Python `dict` 对象的创建方式 | 创建字典 |

日常交流中说“Python 内置的 `enumerate`”或“JavaScript 内置的 `Map`”都没问题；需要精确表达时，再分别补上“函数”和“对象类型/构造函数”。不要把它们统称为“内置方法”，因为 `enumerate` 并不依附于某个实例，而 `Map` 本身也不是方法。

**建议**

复习语言 API 时，顺手给知识点标上“函数 / 类型 / 实例 / 方法 / 运算符”之一。这个分类会比只背拼写更容易迁移到新代码中。
