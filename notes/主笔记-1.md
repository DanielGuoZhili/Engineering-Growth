**Two Sum：用 Map 在一次遍历中寻找配对**

### 我的原始内容

原稿包含 JavaScript 与 Python 两种 `twoSum` 实现。我的主要观察是：算法本身不难，当前更需要恢复对两门语言内置工具的熟悉度，尤其是 JavaScript `Map` 的 `has`、`get`、`set`，以及 Python 的 `enumerate`。我也希望 Saber 判断思路是否正确，并补全遗漏。

JavaScript 原始代码：

```javascript
/**
 * @param {number[]} nums
 * @param {number} target
 * @return {number[]}
 */
var twoSum = function(nums, target) {
    const map = new Map();

    for(let i = 0; i < nums.length; i++){
        let num = nums[i];
        let complement = target - num;

        if(map.has(complement)){
            return[map.get(complement), i];
        }

        map.set(num, i);
    }

};
```

Python 原始代码：

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        # 1. 设定一个空的字典作为容器（用来存：数字 -> 下标）
        seen = {}

        # 2. 遍历数组：用 enumerate 同时拿到下标 i 和当前数字 num
        for i, num in enumerate(nums):

            # 3. 计算补数
            complement = target - num

            # 4. 检查补数在不在字典里
            if complement in seen:
                # 如果在，说明找到了！返回之前那个数的下标和当前的下标 i
                return [seen[complement], i]

            # 如果不在，把当前的数字和下标存进字典，留给后面查
            seen[num] = i
```

### Saber 的整理

两种实现采用同一个“边遍历、边查找”的算法模式：

1. `map` 保存已经遍历过的数字，以及它们对应的下标。
2. 遍历到 `nums[i]` 时，计算与它组成 `target` 所需的另一个数字 `complement`。
3. 如果 `complement` 已经在 `map` 中，就返回旧下标和当前下标。
4. 如果不存在，再把当前数字和下标放入查找表，供后面的元素使用。

JavaScript 用一个 `Map` 实例表达“数字 → 下标”；如果改写成 TypeScript，可以把它标注为 `Map<number, number>`。Python 用 `dict[int, int]` 表达同一映射。`enumerate(nums)` 只是让 Python 在遍历元素时同时提供下标和值，不改变算法本身。

这里最关键的顺序是**先查找，再写入当前元素**。这避免了在某些输入中把同一个下标使用两次，同时仍能正确处理 `[3, 3]`、`target = 6` 这种需要两个相同数值的情况。

### Saber 的审阅与点评

**结论**：Master 的整体思路正确，而且 JavaScript 与 Python 版本是同一算法的忠实对应。在 LeetCode Two Sum 的常见约定——恰好存在一个答案，并且同一个元素不能使用两次——下，进入第 `i` 次循环时，查找表只包含下标小于 `i` 的元素；如果补数存在，返回的一定是两个不同下标。

**复杂度**：在 JavaScript `Map` 查找和写入平均为常数时间的假设下，时间复杂度是 `O(n)`，额外空间复杂度是 `O(n)`。这里的 `O(1)` 查找是平均情况的实现假设，不应表述成对所有哈希表实现都无条件成立。

**边界情况**：

- 重复数字：先查后存的顺序可以处理 `[3, 3]`。
- 负数与零：补数计算仍然适用。
- 没有答案：函数会自然返回 `undefined`。如果题目不保证一定有答案，需要先明确期望是返回空数组、抛错，还是返回其他值。
- 多个答案：当前实现返回遍历过程中最先发现的一组；是否符合要求取决于题目约定。

**代码表达可以改进的地方**：JavaScript 中的 `num` 和 `complement` 在每轮循环中都不会重新赋值，使用 `const` 能更准确表达意图；`return [`、`for (` 等空格调整可以提升可读性。这些是风格改进，不影响核心算法正确性。Python 版本在题目保证有答案时没有问题；若题目不保证有答案，类型标注 `-> list[int]` 与实际可能隐式返回 `None` 不一致，需要改成 `list[int] | None`，或者明确约定无答案时的行为。

**本地验证结果**：JavaScript 与 Python 两个版本在以下 5 组测试中结果一致且符合预期；这是本地函数级验证，不代表已经在 LeetCode 提交通过。

| `[3, 2, 4]` | `6` | `[1, 2]` | `[1, 2]` |

### Q-20261101-001

**`enumerate`、`Map` 应该称为内置方法还是对象？**

**问题**

Python 的 `enumerate` 和 JavaScript 的 `Map` 应该怎样准确称呼？它们是内置方法，还是对象？

**结论**

- Python `enumerate` 是**内置函数（built-in function）**。调用它会返回一个 `enumerate` 迭代器对象；遍历时依次产生 `(下标, 元素)` 二元组。
- JavaScript `Map` 是语言提供的**内置对象类型/内置构造函数**；`new Map()` 创建一个 `Map` 实例。
- `map.has()`、`map.get()`、`map.set()` 是 `Map` 实例使用的**方法**，更准确地说是定义在 `Map.prototype` 上的实例方法。
- Python 代码里的 `seen = {}` 创建的是一个 `dict`（字典）对象。`complement in seen` 使用的是成员运算符，`seen[num] = i` 是按键写入；它们都不应称为 `dict` 方法。

**分析**

可以用下面这组层次来记忆：

| 代码 | 准确称呼 | 作用 |
| --- | --- | --- |
| `enumerate` | Python 内置函数 | 把可迭代对象包装成“下标 + 元素”的迭代器 |
| `enumerate(nums)` | `enumerate` 迭代器对象 | 迭代时产生 `(index, value)` |
| `Map` | JavaScript 内置对象类型 / 构造函数 | 描述键值映射集合 |
| `new Map()` | `Map` 实例对象 | 保存本题中的“数字 → 下标” |
| `map.has/get/set` | `Map` 的实例方法 | 检查、读取、写入键值 |
| `{}` / `dict()` | Python `dict` 对象的创建方式 | 创建字典 |

日常交流中说“Python 内置的 `enumerate`”或“JavaScript 内置的 `Map`”都没问题；需要精确表达时，再分别补上“函数”和“对象类型/构造函数”。不要把它们统称为“内置方法”，因为 `enumerate` 并不依附于某个实例，而 `Map` 本身也不是方法。

**建议**

复习语言 API 时，顺手给知识点标上“函数 / 类型 / 实例 / 方法 / 运算符”之一。这个分类会比只背拼写更容易迁移到新代码中。

### 我的原始内容

这是 LeetCode 121「买卖股票的最佳时机」的 JavaScript 与 Python 实现。我的主要笔记点是：

- `minPrice` 初始化为正无穷非常重要；如果写成 `0`，第一轮的逻辑会出问题，但具体原因还需要 Saber 整理。
- JavaScript 的 `Infinity` 在 Python 中可以写成 `float('inf')`。
- JavaScript 的 `else if` 对应 Python 的 `elif`。
- JavaScript 使用花括号表示代码块，Python 使用冒号和缩进。

JavaScript 原始代码：

```javascript
/**
 * 121. Best Time to Buy and Sell Stock
 * @param {number[]} prices
 * @return {number}
 */
var maxProfit = function(prices) {
    let minPrice = Infinity; // 初始化历史最低价为无穷大
    let maxProfit = 0;       // 初始化最大利润为 0

    for (let i = 0; i < prices.length; i++) {
        // 1. 更新历史最低价：看看今天是不是更便宜
        if (prices[i] < minPrice) {
            minPrice = prices[i];
        }
        // 2. 计算如果今天卖出的利润，并更新最大利润
        else if (prices[i] - minPrice > maxProfit) {
            maxProfit = prices[i] - minPrice;
        }
    }

    return maxProfit;
};
```

Python 原始代码：

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        minPrice = float('inf')
        maxProfit = 0

        for i in prices:
            if i < minPrice:
                minPrice = i
            elif i - minPrice > maxProfit:
                maxProfit = i - minPrice

        return maxProfit
```

### Saber 的整理

这道题的核心不是枚举所有买入日和卖出日，而是在从左到右的一次遍历中维护两个状态：

1. `minPrice`：截至今天为止见过的最低价格。
2. `maxProfit`：截至今天为止，在“先买后卖”的约束下能够得到的最大利润。

遍历到当天价格时，先判断它是否刷新历史最低价；如果没有，再计算“以今天作为卖出日”能够得到的利润。这样就不会使用未来的价格作为过去的买入价。

可以把循环中的不变量理解为：处理完第 `i` 天后，`minPrice` 等于前 `i + 1` 天的最低价格，`maxProfit` 等于这段日期范围内所有合法交易的最大利润；如果始终无法盈利，则保持为 `0`。

两种语言在本题中的对应关系如下：

| JavaScript | Python | 准确理解 |
| --- | --- | --- |
| `Infinity` | `float('inf')` 或 `math.inf` | 正无穷数值，可作为“尚未见到真实价格”的哨兵值 |
| `else if` | `elif` | 在前一个条件不成立时继续判断 |
| `{ ... }` | `:` 加缩进 | 表示条件、循环或函数的代码块 |
| `prices[i]` | `price`（直接遍历） | 当前价格；Python 此处不需要下标 |

### Saber 的审阅与点评

**结论**：Master 的整体算法正确。这是一种单次遍历的贪心写法，也可以理解为维护“运行中的最低值和最佳答案”。关键并不只是记住 `Infinity`，而是理解 `minPrice` 在任何一轮都必须代表已经实际出现过的最低价格。

**复杂度**：JavaScript 和 Python 两个版本都只遍历数组一次，因此时间复杂度为 `O(n)`；只额外保存两个数值，因此额外空间复杂度为 `O(1)`。

**关于 `else if` / `elif`**：当前写法正确。当今天刷新最低价时，同一天买入再卖出的利润只能是 `0`，不会超过非负的 `maxProfit`，所以不必继续计算。即使改成第二个独立的 `if`，在更新 `minPrice` 后算出的也只是 `0`，通常仍然正确，但会多做一次没有意义的判断。

**Python 命名**：`for i in prices` 中的 `i` 实际表示价格而不是下标。改成 `for price in prices`，再写 `price < minPrice`，会更容易读懂，也能避免把它误认为索引。

**本地验证结果**：两个版本在以下 6 组测试中结果一致并符合预期；这是本地函数级验证，不代表已经在 LeetCode 提交通过。

| `prices` | 预期最大利润 | JavaScript | Python |
| --- | ---: | ---: | ---: |
| `[7, 1, 5, 3, 6, 4]` | `5` | `5` | `5` |
| `[7, 6, 4, 3, 1]` | `0` | `0` | `0` |
| `[1, 2]` | `1` | `1` | `1` |
| `[2, 1]` | `0` | `0` | `0` |
| `[5]` | `0` | `0` | `0` |
| `[]` | `0` | `0` | `0` |

Master，这次你抓到的是一个很有迁移价值的知识点：初始化值并不是随便选一个“看起来不会冲突”的数字，而是要服务于循环不变量。你已经注意到 `0` 会造成问题；把原因进一步落实到“它不是数组中真实出现过的最低价”，理解就完整了。

### Q-20261103-001

**`Infinity` 为什么适合作为历史最低价的初始值？**

**问题**

`minPrice` 为什么要初始化为 `Infinity`？如果写成 `0`，是不是会在第一轮失败，导致无法进入下一轮循环？Python 的 `float('inf')` 又应该怎样准确理解？

**结论**

`Infinity` 的作用是一个**哨兵值**：在题目价格都是有限数值的前提下，第一个价格一定小于它，所以第一次循环必然会把 `minPrice` 更新成真实出现过的价格。

如果初始化为 `0`，循环仍然会正常执行每一轮；真正的问题是，当股票价格都是非负数时，没有价格会小于 `0`，于是 `minPrice` 一直错误地保持为 `0`。程序随后会计算出仿佛曾以价格 `0` 买入的利润，破坏了“买入价必须来自数组”的条件。

**分析**

以 `[7, 1, 5, 3, 6, 4]` 为例：

- 正确初始化为 `Infinity` 时，第一轮会把 `minPrice` 更新为 `7`，之后再更新为 `1`，最终得到利润 `6 - 1 = 5`。
- 错误初始化为 `0` 时，第一天的 `7` 不小于 `0`，程序会直接把 `7 - 0 = 7` 当成利润。循环没有停止，但答案已经建立在一个并不存在的买入价格上。

因此，问题不是“无法进入下一轮”，而是 `minPrice` 从一开始就不符合它应该表达的含义。

Python 的 `float('inf')` 是把 Python 能识别的字符串 `'inf'` 转换为一个表示正无穷的浮点数；它不是“浮点数加上字符串”。也可以先 `import math`，再使用 `math.inf`。JavaScript 中的 `Infinity` 则是一个数值，`typeof Infinity` 的结果是 `"number"`。

另一种同样正确的写法是把 `minPrice` 初始化为 `prices[0]`，然后从第二个价格开始遍历。这种方式不依赖无穷大哨兵，但需要先确认数组非空；使用 `Infinity` 则能让初始化更统一。

**建议**

可以把这个模式记成：“寻找运行中的最小值时，用一个保证大于所有合法输入的初值，让第一个真实输入自然接管状态。”不过在有明确上下界时，也要确认哨兵值不会被误当成真实数据。
