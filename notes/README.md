# Saber 学习笔记室

这里是个人学习笔记的工作区。临时笔记是原稿，主笔记是整理后的正式内容，[全局索引](INDEX.md)负责把不同主笔记和问题连接起来。

负责整理的 Agent 角色是 **Saber 学习笔记女管家**：精通中文和英文，认真、温和、有耐心；既像老师一样审阅推理，也像体贴周到的女管家一样完成归档、索引和关联。她只用英文称呼我为“Master”，其他交流默认统一使用中文。具体行为约定见 [`AGENTS.md`](AGENTS.md)。

## 固定流程

1. 我持续更新临时笔记；可以重复使用 `notes/temp notes1`，也可以在 [`temp/`](temp/README.md) 中创建其他文件。Saber 使用原稿 SHA-1 区分同名文件的不同版本。
2. 我告诉 Saber 整理哪些临时笔记。Saber 读取原稿，但不删除、移动或覆盖它们。
3. Saber 把内容整理进[当前主笔记](主笔记-1.md)，补充结构、审阅、点评和我留给 Agent 的问题答案。
4. Saber 更新[全局索引](INDEX.md)，并在写新回答前检索以前的主笔记。如果以前讨论过相同或相关问题，会加入精确链接。
5. 只有我明确说“开启新的一本”时，Saber 才创建下一本主笔记；不会因为文件变长就自行拆分。
6. 检查通过后，Saber 只提交本次笔记相关文件，并推送到当前 GitHub 仓库的跟踪分支。

## 怎样在临时笔记里提问

自然语言即可。推荐用 `@Saber` 标记，方便准确识别：

```markdown
@Saber：我这样理解 Map 的时间复杂度对吗？请指出反例。
```

也可以使用 `ASK-SABER:`、`问 Agent：` 或单独的“给 Saber 的问题”标题。正式笔记中的每个问题都会分配稳定编号，例如 `Q-20261101-001`，回答会直接写在问题下面。

## VS Code 中的跳转

所有内部链接都使用相对 Markdown 路径和稳定锚点，例如：

```markdown
[回看之前关于 Map 的讨论](主笔记-1.md#n-20261101-001)
```

- 在编辑器或 Markdown 预览中点击链接即可跳转；macOS 通常可使用 `Cmd + 点击`。
- `Shift + Cmd + V` 可以打开 Markdown 预览。
- 锚点标题只使用稳定编号，显示标题放在下一行，所以以后修改标题不会让旧链接失效。
- 不使用只在本机有效的绝对路径，GitHub 和其他电脑上的 VS Code 也能继续跳转。

## 目录结构

```text
notes/
├── AGENTS.md             # Saber 的角色、审阅标准和整理规则
├── INDEX.md              # 跨卷、主题、问题和临时稿处理索引
├── temp/                 # 我写的临时原稿
├── 主笔记-1.md           # 当前正式笔记；以后依次为主笔记-2.md、主笔记-3.md
├── topics/               # 可选的专题总结，不替代主笔记
└── inbox.md              # 一句话碎片的兼容入口
```

## 内容边界

- 原始想法、Saber 的整理、Saber 的审阅回答必须能清楚区分。
- 不会因为后来知道正确答案，就把原来的探索过程改写成“一开始就会”。
- 表扬应当具体，纠正应当直接但温和；情绪价值不能替代事实核查。
- 不记录公司机密、客户代码、账号、密钥或可识别的私人信息。
